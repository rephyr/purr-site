A real run

Why small models do better here

Small models slip. purr expects it: a lean prompt, limits that fit the model's context, and a harness that catches the slips instead of failing on them.

  1. 32k context 72% full
    ✓ the older chat becomes a short summary

    Limits fit the model's context.

  2. edit_file src/stats.py indented 6 spaces, the file uses 4
    ✓ matched ignoring indent, re-indented

    Fuzzy edits still apply.

  3. writes <function=run><parameter=command>pytest -q… as plain text
    ✓ ran it as a tool call

    Tool calls written as text still run.

  4. edit_file src/report.py ✗ ruff F821 undefined name
    ✓ syntax ✓ ruff, after the model's fix

    Every Python edit gets checked.

  5. edit_file src/stats.py the 8th change, still failing
    ↺ a step back: what's known, why it fails, a new approach

    Loops get caught.

  6. wants to say "done"
    purr runs the tests ✓ 3 passed, reads the request again

    Done means checked: purr runs the tests, then the model reads the request again.

  7. plan mode a big model writes three tickets
    ✓ a small model does them one by one

    Big jobs become small tickets.

Acted out, not a real log. The numbers are purr's own settings: a step back after 8 changes to the same file; on a context of 40k or less, old tool output is folded away at 60% and the chat summarised at 72% (both later on bigger ones).

Modes

shift+tab switches modes. Each one gives purr a different job.

✎codedoes the work (the default)
◈asklooks around, never changes anything
✿learnleaves the key lines for you to write
⇄pairyou take turns, one step each
✦plana big model writes tickets, a small one does them
♥chatjust talking
✧createideas, names and stories

Your own agent is a Markdown file in ~/.config/purr/agents/, or /agent new reviews my code and purr writes it. Agents from Claude Code and OpenCode work too.

Before edits and commands purr asks: y yes · a always · n no, or type what to do instead; /undo puts back what the last answer changed. On a local model, a short first task is rewritten as Task / Where / Steps / Done when for you to check: ctrl+s sends it, ctrl+o sends yours. More in the guide.

Yours

No telemetry, no account. purr talks only to the model you pick, the pages the model fetches, and GitHub for Godot docs. Chats are saved on your machine (~/.local/state/purr). /private switches to local models only: no web, and the chat isn't saved. Free hosts may keep your prompts: use a local model or /private for private code.
